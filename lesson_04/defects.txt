DEF-01. Метод trim: не удаляет табы и переводы строк в начале
------------------------------------------------------------
Приоритет:    Средний
Серьёзность:  Средняя
Тип:          Функциональный дефект

Описание:
    Метод trim задуман как «удаляет пробелы в начале строки». Однако
    реализация удаляет только символ обычного пробела (" "), а табы ("\t")
    и переводы строк ("\n") в начале строки оставляет.

Шаги воспроизведения:
    1. Вызвать string_utils.trim("\tskypro")
    2. Вызвать string_utils.trim("\nskypro")

Фактический результат:
    "\tskypro"  -> "\tskypro"   (таб остался)
    "\nskypro"  -> "\nskypro"   (перевод строки остался)

Ожидаемый результат:
    Пробельные символы (пробел, таб, перевод строки) должны удаляться
    в начале строки. Ожидалось: "skypro" и "skypro" соответственно.

Влияние:
    Пользователь может получить "грязные" строки с невидимыми символами
    в начале, что приведёт к ошибкам сравнения и поиска.

Рекомендация:
    Использовать string.lstrip() без аргументов (удаляет все пробельные
    символы) либо явно указать набор: string.lstrip(" \t\n\r\f\v").

DEF-02. Метод contains: пустая строка symbol возвращает True
------------------------------------------------------------
Приоритет:    Низкий
Серьёзность:  Низкая
Тип:          Пограничный случай / неопределённое поведение

Описание:
    При передаче пустой строки в качестве symbol метод contains всегда
    возвращает True, даже если строка string пустая. Это не отражено
    в документации и может вводить в заблуждение.

Шаги воспроизведения:
    1. string_utils.contains("SkyPro", "")
    2. string_utils.contains("", "")

Фактический результат:
    True и True

Ожидаемый результат:
    Поведение не задокументировано. Требуется уточнить у заказчика:
    либо возвращать False на пустой symbol, либо явно описать
    текущее поведение в docstring.

Влияние:
    Может привести к логическим ошибкам в коде, который использует
    contains для валидации пользовательского ввода.

Рекомендация:
    Добавить в docstring описание поведения для пустого symbol
    или явно обработать этот кейс (например, вернуть False).

DEF-03. Методы capitalize / trim / delete_symbol: AttributeError на None
------------------------------------------------------------
Приоритет:    Низкий
Серьёзность:  Низкая
Тип:          Качество обработки ошибок

Описание:
    При передаче None вместо строки методы падают с AttributeError,
    а не с более информативным TypeError. Сообщение об ошибке не
    объясняет пользователю, что именно пошло не так.

Шаги воспроизведения:
    1. string_utils.capitalize(None)
    2. string_utils.trim(None)
    3. string_utils.delete_symbol(None, "a")

Фактический результат:
    AttributeError: 'NoneType' object has no attribute 'capitalize'
    (аналогично для остальных методов)

Ожидаемый результат:
    Явная проверка типа и выброс TypeError с понятным сообщением,
    например: "Ожидалась строка, получен NoneType".

Влияние:
    Затрудняет отладку для того, кто пользуется библиотекой.

Рекомендация:
    Добавить проверку isinstance(string, str) в начале каждого метода
    и выбрасывать TypeError с понятным текстом.

DEF-04. Метод delete_symbol: не задокументировано поведение
        с пустой подстрокой
------------------------------------------------------------
Приоритет:    Низкий
Серьёзность:  Низкая
Тип:          Документация

Описание:
    Метод delete_symbol на пустой symbol возвращает исходную строку
    без изменений. Это поведение не описано в docstring.

Шаги воспроизведения:
    1. string_utils.delete_symbol("SkyPro", "")

Фактический результат:
    "SkyPro" (без изменений)

Ожидаемый результат:
    Поведение должно быть либо задокументировано, либо symbol=""
    должно вызывать ошибку как некорректный вход.

Влияние:
    Скрытое поведение может привести к неожиданным результатам
    в коде, где symbol приходит из внешнего источника.

Рекомендация:
    Дополнить docstring или валидировать вход.
